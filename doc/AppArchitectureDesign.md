# TheBook App 整体设计

> 文档状态：整体方案初稿  
> 更新日期：2026-09-01  
> 适用范围：TheBook 主体架构、导航体系、核心模块与全局交互

## 1. 产品定位

TheBook 是一个仅供个人使用的、本地优先的生活记录与工具中心。它不是单一用途的记账、任务或备忘录 App，而是由多个相对独立的个人功能组成的统一容器。

当前及计划中的主要能力包括：

- 账单管理：导入并解析支付宝、微信等来源的账单，转换为 TheBook 的统一账单格式。
- 行为记录：定义 Action、Habit、Task 等对象，记录日常行为和习惯。
- 时间管理：纪念日、生日、倒数日、重复日程及提醒。
- 内容记录：感想、备忘录及其他个人文本。
- 专注管理：番茄钟、专注状态和历史统计。
- 健康管理：接收穿戴设备和华为运动健康相关 SDK 提供的健康数据，进行统一展示与统计。
- 工具箱：NFC 读写、文件加解密、蓝牙等工具。
- 数据管理：数据导入导出、完整备份、恢复、工作目录和安全设置。

TheBook 的整体设计目标不是隐藏功能数量，而是通过清晰分层，让高频功能容易到达、低频功能容易查找、正在执行的操作不会丢失。

## 2. 核心设计原则

### 2.1 一个统一外壳，多个独立模块

各功能共享 App 外壳、导航、主题、搜索、备份和安全能力，但账单、行为记录、日程、感想和工具不应被强行合并为同一种业务模型。

统一的是：

- 页面框架和视觉语言。
- 导航和快捷操作入口。
- 数据备份与安全策略。
- 搜索、标签等真正具有通用价值的能力。

保持独立的是：

- 各模块的数据库实体和业务规则。
- 权限申请和设备能力。
- 编辑、导入、统计等具体流程。

### 2.2 导航与操作分离

- 导航回答“去哪里”，例如进入账单、任务或日程页面。
- 快捷操作回答“现在做什么”，例如记一笔、写感想或新建任务。
- 一次性操作不得伪装成底部导航入口。

### 2.3 高频入口可配置，完整功能始终可达

底部导航代表当前最常使用的五个页面，可以调整顺序和替换；左侧边栏保存完整功能目录，因此任何模块都不会因为未被放到底部而消失。

### 2.4 根工作区支持横向切换，详情页保持稳定

配置在底部导航中的五个根页面可以左右滑动切换。编辑器、图表、NFC、蓝牙、文件处理、账单导入等详情页面不参与全局横向切换，避免和选择文字、拖动图表及设备操作产生手势冲突。

### 2.5 个人使用优先

设计优先满足固定使用者的效率和习惯，不必为了应用市场、首次引导或通用用户偏好增加额外复杂度。但数据安全、误操作保护、备份可恢复性和权限边界仍必须严格处理。

## 3. 全局信息架构

TheBook 使用三层入口：左侧边栏、可配置底部导航、可拖动快捷球。

| 导航层 | 职责 | 典型内容 |
| --- | --- | --- |
| 左侧边栏 | 完整功能地图 | 全部业务模块、数据管理、设置、关于 |
| 底部五项 | 最常用的五个根页面 | 首页、账单、番茄钟、感想、任务 |
| 可拖动快捷球 | 立即创建或执行 | 记一笔、写感想、新建任务、记录行为、添加日程 |

整体结构示意：

```text
MainActivity
├── 左侧边栏：全部功能目录
├── 顶部栏：菜单、页面标题、搜索及页面操作
├── 主内容区：当前根页面或详情页面
├── 可拖动快捷球：全局快速操作
└── 底部导航：五个可配置常用页面
```

## 4. 底部导航设计

### 4.1 默认配置

当前暂定的默认五项为：

```text
首页　账单　番茄钟　感想　任务
```

默认顺序同样可以修改。底部导航的定位是“常用页面收藏夹”，不是写死的产品模块清单。

### 4.2 可选模块池

第一阶段可以提供以下候选页面：

- 首页
- 账单
- 番茄钟
- 感想
- 任务
- 行为记录
- 日程管理
- 纪念日与倒数日
- 备忘录
- 统计
- 健康
- 工具箱
- 数据管理

只有具有持续页面状态的目的地可以放入底部导航。以下一次性操作不得作为底部入口：

- 记一笔。
- 新建任务。
- 写感想。
- 导入支付宝或微信账单。
- 扫描 NFC。
- 开始加密文件。

这些操作属于快捷球或页面内部操作。

### 4.3 配置规则

- 第一版始终保留五个位置。
- 五项必须唯一，不允许重复模块。
- 所有位置均可替换，所有项目均可重新排序。
- 左侧边栏始终保留完整模块入口，因此不强制把首页固定在底部。
- 配置损坏、模块失效或数量不足时，使用默认模块自动补齐。
- 当前页面被移出底部导航时，优先返回首页；首页未配置时，返回新的第一项。
- 配置保存后立即刷新导航，不要求重启 App。
- 提供“恢复默认配置”。

### 4.4 配置交互

侧边栏中提供：

```text
界面与导航
├── 编辑底部导航
└── 编辑快捷操作
```

底部导航编辑页面显示五个当前位置，支持长按拖动排序、点击替换和保存预览。也可以长按底部任意入口，直接打开编辑页面并定位到对应位置。

### 4.5 配置存储

持久化稳定的模块 Key，不保存 Fragment 类名、数组序号或临时资源 ID。例如：

```json
[
  "home",
  "bill",
  "pomodoro",
  "thought",
  "task"
]
```

程序内部通过模块注册表将 Key 映射到标题、图标和导航目的地。模块 Key 一旦发布并产生用户配置，不应随意修改。

底部导航配置和快捷操作配置应包含在完整配置备份中，以便重装后恢复个人使用习惯。

### 4.6 徽标状态

底部入口可以显示与模块绑定的徽标：

- 任务：今天未完成的任务数。
- 日程：即将触发的提醒数。
- 账单：待确认或导入失败的账单数。
- 番茄钟：运行中显示状态点，完成后显示待确认提示。

徽标绑定模块 Key，而不是底部位置，调整顺序后仍指向正确模块。

## 5. 左侧边栏设计

左侧边栏是完整且稳定的功能目录，从屏幕左边缘向右滑动打开，也可以点击顶部栏左侧菜单按钮打开。

建议分组：

```text
TheBook

常用
├── 首页
├── 账单
├── 番茄钟
├── 感想
└── 任务

记录与内容
├── 行为记录
├── 习惯
├── 备忘录
└── 统计

健康
├── 健康概览
├── 运动与活动
├── 睡眠
├── 心率等身体指标
└── 数据同步与来源

时间
├── 日程管理
├── 纪念日
├── 生日
└── 倒数日

工具箱
├── NFC
├── 文件加解密
└── 蓝牙

数据与系统
├── 账单导入

├── 完整备份与恢复
├── 工作目录

├── 设置

```

分组可以折叠。“常用”默认展开，工具和数据类分组可以默认折叠。侧边栏入口对应页面，不直接执行破坏性操作。

## 6. 横向页面切换与返回规则

### 6.1 根页面切换

底部配置顺序同时决定横向分页顺序。使用默认配置时：

```text
首页 ←→ 账单 ←→ 番茄钟 ←→ 感想 ←→ 任务
```

- 点击底部按钮直接切换根页面。
- 在根页面内容的普通区域左右滑动，切换相邻根页面。
- 切换时同步底部选中状态。
- 页面应保留滚动位置、输入草稿和已加载状态。

### 6.2 侧边栏手势

- 从屏幕左边缘开始向右滑动：打开侧边栏。
- 侧边栏打开后向左滑动：关闭侧边栏。
- 点击侧边栏外的遮罩：关闭侧边栏。
- 左上角菜单按钮始终保留，边缘手势不是唯一入口。

Android 系统返回手势同样占用屏幕边缘，因此不得依赖大范围系统手势排除；需要优先保证系统返回可用。

### 6.3 详情页面

以下页面不参与根页面横向切换：

- 感想和备忘录编辑器。
- 任务编辑及详情。
- 账单详情和导入预览。
- 图表拖动与缩放区域。
- NFC 读写页面。
- 蓝牙扫描和连接页面。
- 文件加解密页面。
- 设置和数据恢复页面。

详情页返回顺序为：

```text
先收起快捷菜单
→ 再关闭侧边栏或弹层
→ 再返回上一页面
→ 根页面再次返回时退出 App
```

## 7. 可拖动快捷球

### 7.1 定位

快捷球是全局的快速操作中心，不是系统悬浮窗。它只显示在 TheBook 内部，不申请“显示在其他应用上层”权限。

快捷球位于 Activity 级别，切换 Fragment 或底部页面时保持位置和状态。

### 7.2 基本行为

- 可以在 App 内容区域内拖动。
- 拖动结束后自动吸附到距离最近的左右边缘。
- 记录吸附边和纵向比例，下次启动恢复位置。
- 不得进入状态栏、系统导航栏或覆盖底部导航。
- 横竖屏或窗口尺寸改变时，根据比例重新计算位置。
- 拖动开始时自动收起已展开菜单。
- 点击快捷球展开或收起操作菜单。
- 点击菜单外部或按返回键收起菜单。

### 7.3 拖动与点击识别

- 按下时记录手指和控件初始坐标。
- 移动距离超过系统 `touchSlop` 后进入拖动状态。
- 未超过阈值的抬起事件视为点击。
- 拖动结束不得同时触发点击和展开。
- 快捷球只拦截自身及展开菜单区域的触摸，不能影响页面其他区域的横向滑动、图表操作和文字选择。

### 7.4 展开方向

快捷操作菜单根据所在位置向屏幕内部展开：

- 吸附右侧时向左侧或左上方展开。
- 吸附左侧时向右侧或右上方展开。
- 靠近底部时向上展开。
- 靠近顶部时向下展开。

优先使用带图标和文字的纵向快捷列表，避免五个以上图标组成难以识别的放射菜单。

### 7.5 默认快捷操作

建议第一版默认提供：

```text
记一笔
记录行为
写感想
新建任务
添加日程
```

快捷操作后续可独立配置，配置内容与底部导航互不影响。

### 7.6 实现方向

使用官方 Material `FloatingActionButton` 作为主按钮外观，自定义 `DraggableQuickActionMenu` 负责：

- 拖动边界计算。
- 左右吸附动画。
- 展开与收起。
- 点击外部关闭。
- 位置持久化。
- 与页面、锁屏状态的协调。

不依赖长期无人维护的第三方 Arc Menu、Boom Menu 或系统悬浮窗库。

## 8. 五个默认根页面

### 8.1 首页

首页是跨模块聚合仪表盘，默认展示与“今天”有关的信息，而不是复制各业务模块的完整功能。

建议卡片：

- 今日消费与本月消费摘要。
- 当前番茄钟或今日专注时长。
- 今日任务及完成进度。
- 今日行为记录摘要。
- 今日步数、睡眠、运动等健康摘要。
- 最近感想或备忘。
- 即将到来的生日、纪念日和倒数日。
- 常用快速操作。

首页卡片后续可以支持调整顺序和隐藏；第一版按照实际使用频率固定布局即可。

### 8.2 账单

账单模块负责统一管理手工账单和外部导入账单。

建议子页面：

```text
账单
├── 流水
├── 账户
├── 分类
├── 统计
└── 导入
    ├── 支付宝解析器
    ├── 微信解析器
    ├── 其他来源解析器
    └── 自定义格式
```

统一账单模型至少包含：

- 交易时间。
- 金额。
- 收入或支出方向。
- 商户或交易对象。
- 分类。
- 支付账户。
- 原始描述。
- 数据来源。
- 来源流水号。
- 备注。

导入流程必须为：

```text
选择文件
→ 识别来源与编码
→ 解析为中间模型
→ 预览
→ 去重
→ 确认分类映射
→ 用户确认
→ 事务写入
```

任何外部账单都不得在缺少预览和确认的情况下直接写入正式数据。

### 8.3 番茄钟

番茄钟作为默认底部入口，负责：

- 快速选择专注时长。
- 开始、暂停、继续和结束。
- 显示当前剩余时间。
- 关联任务或行为记录。
- 查看当天和历史专注统计。
- 后台通知和完成提醒。

由于番茄钟已经是常驻底部入口，第一版不额外增加占据页面宽度的全局迷你状态条，避免与五项底部导航和快捷球同时出现造成拥挤。运行中可以通过以下方式保持可见性：

- 底部“番茄钟”入口显示运行状态点或徽标。
- 系统通知显示精确剩余时间和控制按钮。
- 首页显示当前专注卡片。

后续如果实际使用证明仍需要，可以再增加可选的紧凑状态条。

### 8.4 感想

感想定位为带时间属性的个人思考、日记和灵感记录，强调内容和当时状态，而不是待办事项。

建议能力：

- 标题和正文。
- 创建时间和最后修改时间。
- 标签、置顶和归档。
- 可选的心情、天气或关联事件。
- 搜索和时间线浏览。
- 自动保存草稿。

第一版优先采用可靠的纯文本或 Markdown，不急于实现复杂富文本编辑器。

“感想”和“备忘录”可以共享部分编辑、标签和搜索基础设施，但语义保持不同：

- 感想：记录已经产生的思考和体验。
- 备忘录：保存未来可能需要查阅的信息。

### 8.5 任务

任务模块负责具有完成状态的事项，不与单次行为记录混为一体。

建议能力：

- 标题、说明、优先级和状态。
- 开始时间、截止时间和提醒。
- 子任务。
- 标签和项目分组。
- 与番茄钟关联。
- 与 Action/Habit 关联但不强制依赖。
- 今天、即将到期、已完成和全部任务视图。

概念边界：

- `ActionDefinition`：可被反复记录的行为定义，例如“跑步”。
- `ActionRecord`：某个行为真实发生的一次记录，例如“今晚跑步 5km”。
- `Habit`：反复执行的目标，例如“每周跑步三次”。
- `Task`：具有完成状态的事项，例如“周六购买跑鞋”。

## 9. 其他业务模块

### 9.1 日程、纪念日与提醒

日程模块通过侧边栏完整进入，并在首页展示最近内容。计划支持：

- 普通日程。
- 生日、纪念日和倒数日。
- 公历或农历。
- 每年、每月或自定义周期重复。
- 提前若干天提醒和当天提醒。
- 距离上次或下次的天数。
- 备注、关联人员和是否在首页展示。

提醒调度必须与页面解耦，即使 App 未处于前台，也能按照 Android 系统允许的方式触发通知。

### 9.2 备忘录

备忘录通过侧边栏和首页最近卡片进入，建议支持：

- 标题、正文、置顶、标签和归档。
- 创建及修改时间。
- 可选提醒。
- 全局搜索。
- 纯文本或 Markdown。

### 9.3 行为记录和统计

行为记录模块负责 Action、Habit 和 ActionRecord。统计属于业务模块内部视图，不将财务统计和行为统计强行合并为同一张图。

图表区域拥有水平手势优先权，不触发根页面切换。

### 9.4 工具箱

工具箱是多个独立工具的统一入口：

```text
tools
├── nfc
├── bluetooth
├── crypto
└── file
```

各工具只共享统一视觉和入口，不共享无关业务状态。NFC、蓝牙和文件权限按需申请，不在 App 启动时集中索取。

### 9.5 健康

健康是独立业务模块，也是底部导航的可选根页面。当前默认五项保持不变；需要高频查看健康数据时，可以把“健康”替换到底部任意位置。

健康模块预计接入以下数据来源：

- 穿戴设备直接提供的数据。
- 华为运动健康相关 SDK 提供的数据。
- 后续可能增加的其他健康平台或手工记录。

不同来源不得直接把各自的 SDK 数据模型暴露给页面和业务统计。模块内部应建立统一健康模型和数据来源适配层：

```text
穿戴设备数据 ─┐
               ├→ HealthSourceAdapter → 统一健康模型 → 本地数据库 → 页面与统计
华为健康 SDK ─┘
```

第一阶段可考虑的健康数据类型：

- 步数、活动距离、活动热量和站立情况。
- 运动记录、运动类型、时长、距离和能量消耗。
- 睡眠时段、睡眠阶段和睡眠总时长。
- 心率、静息心率和心率区间。
- 血氧、体重等设备能够稳定提供的指标。

统一健康记录至少需要保留：

- 指标类型。
- 开始和结束时间或采样时间。
- 数值、单位及必要的区间信息。
- 数据来源类型。
- 来源记录 ID。
- 穿戴设备 ID 或设备描述。
- 时区信息。
- 导入或同步时间。
- 原始数据版本或必要的来源元数据。

同步设计要求：

- 每个数据来源保存独立同步游标和最后成功同步时间。
- 使用来源记录 ID、指标类型和时间范围等信息去重。
- 同一数据可能由穿戴设备和华为 SDK 重复提供，需要定义来源优先级或合并规则。
- 同步写入使用事务，失败时不得推进同步游标。
- 页面明确显示数据来源和最后更新时间。
- 支持用户手动触发同步，并展示同步中、成功、部分失败和权限失效状态。
- 不在缺少授权时静默生成看似完整的健康统计。

建议页面结构：

```text
健康
├── 概览
├── 活动
├── 睡眠
├── 身体指标
├── 趋势
└── 数据来源与同步
```

健康页面中的图表、时间范围滑动和指标拖动拥有手势优先权，不触发根页面横向切换。首页只展示轻量摘要，完整趋势和来源状态进入健康模块查看。

## 11. 视觉设计

整体借鉴大型内容 App 的层次管理，不复制其商业化信息密度和品牌配色。

- 保留 TheBook 当前绿色品牌色和深色模式。
- 页面背景使用低干扰的浅灰或深灰。
- 主要内容使用圆角卡片承载，圆角建议统一为 12–16dp。
- 减少无意义边框，主要依靠留白、字号和表面色区分层级。
- 绿色用于品牌和正向状态。
- 橙色用于当前进度、提醒和番茄钟。
- 红色只用于失败、删除和危险操作。
- 工具模块可以使用不同辅助图标色，但不改变全局主题。
- 顶部栏、底部导航、侧边栏和快捷球保持统一的 Material 视觉语言。

## 12. 安全与数据保护

### 12.1 App 锁

指纹锁或其他 App 锁必须覆盖整个全局外壳，而不只是当前 Fragment：

- 锁定时关闭并禁止打开侧边栏。
- 隐藏或禁用快捷球。
- 禁止操作底部导航。
- 禁止通过通知、快捷操作或深层链接绕过认证进入敏感页面。
- 解锁后再恢复导航和快捷操作。

### 12.2 导入与恢复

- 所有批量导入必须先预览、去重和确认。
- 覆盖恢复必须明确提示将被替换的数据范围。
- 数据库写入应使用事务，失败时不保留部分结果。
- 完整备份应包含数据库版本、模块版本和配置清单。
- 导航和快捷操作配置属于应备份的个人设置。

### 12.3 破坏性操作

删除、覆盖、清空、恢复和批量修改不得放入侧边栏或底部导航中直接触发，必须进入专用页面并二次确认。

### 12.4 健康数据权限与隐私

- 健康权限按数据类型和实际功能按需申请，不在首次启动时一次性索取全部权限。
- 权限被撤销、授权范围不足或 SDK 不可用时，页面必须显示真实状态。
- 健康数据默认仅保存在本地，不自动发送到外部服务。
- 备份和导出健康数据时明确提示其敏感性，并允许单独排除健康模块。
- 日志、崩溃信息和调试页面不得输出完整健康记录或身份凭据。
- 删除某个健康数据来源时，需要区分“解除来源连接”和“同时删除已同步数据”。

当前阶段可以继续保持单一 Android Application 模块，但在包和数据层面建立边界：

```text
com.seeksky.thebook
├── core
│   ├── navigation
│   ├── search
│   ├── settings
│   ├── security
│   └── backup
├── home
├── finance
├── pomodoro
├── thought
├── task
├── activity
├── health
├── schedule
├── memo
└── tools
    ├── nfc
    ├── bluetooth
    └── crypto
```

不要因为功能多就立即拆成大量 Gradle module。先通过包、接口、Repository 和数据库实体边界降低耦合；当某个模块足够稳定或编译边界确有价值时，再决定是否拆分。

## 14. 推荐的 Activity 外壳

项目继续使用 XML、Fragment、Navigation Component 和 ViewBinding，不要求为了本次架构调整迁移到 Compose。

建议结构：

```text
DrawerLayout
├── 主内容 FrameLayout
│   ├── 页面主体
│   │   ├── MaterialToolbar
│   │   ├── NavHostFragment / 根页面容器
│   │   └── BottomNavigationView
│   ├── DraggableQuickActionMenu
│   └── AppLockOverlay
└── NavigationView
```

关键层级规则：

- 普通页面位于最底层。
- 快捷球覆盖普通页面，但避开底部导航和系统安全区域。
- AppLockOverlay 必须覆盖页面、快捷球和底部导航。
- Drawer 在锁定状态必须强制关闭并禁用手势。
